# Maze Generator and Tester

# User's documentation
To run program, fist navigate to folder of program.

## Before running program
In case random is not installed, run this command in terminal while in the same directory:
```
cabal install --lib containers random
```

## How to Run the program
In console using these commands:
```
ghci Main.hs
main
[WIDTH] [HEIGHT] [LOOPS]
```
When executed, it expects integers separated with whitespace: `width`, `height`, and `probability of loops`.

# Programmer's documentation

## Overview
Main.exe generates a perfect tree with extra edges, that generate loops, which can be interprited as alternative ways from start to finish.
Because crossroads are created by alghorithm itself and then added with user's probability, these are counted in the end. In ideal tree generates a perfect maze and each added edge generates a loop.

Algorithm basicly runs DFS which creates a tree, but for each neighbor which we came from we decide, if there shouldn't be another edge, creating another crossroad and in the end another loop.

Each part has ac omment to it, except for Main.hs, I hope it is intuitive.

## Architecture & Logic

### 1. Data Structures (`MazeTypes.hs`)
* **Config:** Stores the size of the maze and the probability parameter.
* **State:** A helper data structure used during DFS to easily track visited cells, carved paths (edges), and the random seed to avoid passing three separate variables on each call.

### 2. Generation (`MazeGenerator.hs`)
* **Spanning Tree:** The ideal maze is generated by DFS which carves a perfect tree. Neighbors are shuffled to ensure randomness.
* **Cycle Generation:** When `processNeighbors` processes a cell which we came from, and is in `visited`, random generates number between 1 and 100. If this number is less than or equal to the user's probability parameter, it adds another edge, otherwice just skips that visited node.

### 3. Pathfinding & Analysis (`MazeTester.hs`)
* **Shortest Path:** A BFS algorithm calculates the shortest path from the top left to the bottom right cell. Because the cycles create alternative routes, the shortest one counts as the main solution.
* **Crossroad Counting:** Because each new edge that isn't part of the spanning tree creates a crossroad, program goes through each cell and counts those with 3 or 4 edges containing it. 

### 4. Output generation (`MazeDrawer.hs`)
* **Maze Display:** Renders the maze layer by layer, horizontal and vertical rows separately. On top left, and bottom right, there is a missing wall. Rooms (have top and bottom walls) are drawn on odd rows, floors (have left and right walls) are drawn on even rows.
* **Path Display:** A secondary drawer renders just the `*` characters along the broken wall edges that represent the calculated shortest path. These might be confusing, because I print same distance between centers of cells, but it helps to identify the path once you have a maze next to it.
